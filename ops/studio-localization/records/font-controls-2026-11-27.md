# 字体粗细、字号与中文列表

## 用户需求与现行基线

1.0.7 的默认中文显示已由用户确认清晰正常。该版本保留原中文字体，统一字体作为可选；宋体和华文细黑的强制默认都已撤回。用户随后要求加粗、微调字号、去除不能显示中文的字体，以及为实际支持中文的英文家族名显示准确中文名称。

## 实施约定

- 字体家族替换、加粗、字号增量为独立选项。保留默认字体时仍可调整粗细与字号。
- 默认不加粗、字号增量为零；“恢复默认中文”同时撤回本工具的字体和样式覆盖。
- 大标题与小控件保留各自基准，不将全部界面设为同一个字号。反复切换或侧栏刷新不得叠加增量。
- uGUI、TMP 与 IMGUI 各自保存/恢复原样式；粗体选项保留原有斜体及其他样式。输入框需要保留有效行高。
- 列表筛选依据字体本身的中文字符支持能力，而非家族名称是否出现汉字。英文名称的中文字体保留准确家族身份，并提供可读中文显示名。
- 筛选在建立字体列表时执行并缓存，不在逐帧绘制时重新枚举系统字体。原生字体句柄必须释放，系统字体文件不删除或改写。

## 关键边界与复核发现

IMGUI 测量/绘制期间暂用样式，外层结束即恢复；嵌套和样式克隆不叠加增量。uGUI/TMP 使用原状态与上次输出识别外部变化，侧栏在自己的布局基准上应用同一设置。侧栏接管前将控制器拥有的字体还原为会话基准，未激活的克隆控件也先建立记录，避免保存之后可能被淘汰的字体资源。

字体读取只取 SFNT 的名称与字符映射表。一个系统字体不支持 Unicode 名称时，必须跳过该文件而不是中断整个目录；此问题由独立本机核验发现并修复。GDI 实际字体名称表需与文件首字面一致，防系统回退的中文字体冒充请求字体。字体筛选并不修改 Windows 字体安装。

参考机器 660 个登记名称对应 632 个文件，53 次原生探测形成 28 个候选及 48 个受检别名。后台目录构建约 90–145 ms；后续 10,000 次缓存读取约 20 ms 合计。最终仍按 Unity 主线程返回的字体家族进一步筛选，不能把这些数字当所有机器的固定列表或游戏帧率。

独立复核确认真实 ConfigurationManager 19 自定义控件注册、25 层作用域及 7 项所有权 IL 顺序；500 次成功 GDI 查询没有遗留句柄。没有将托管测试、元数据检查或成功查询的资源计数表述为 Unity 实机、所有原生失败路径或全游戏性能证据。统计及候选哈希见[结构化记录](../sources/font-controls-validation.json)。
