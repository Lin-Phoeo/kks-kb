# Studio 翻译与字体性能优化

## 目标与约束

在已验收的宋体默认、字体切换和中文显示上减少重复查找、反射和临时对象。优先复用插件原生语言及控件初始化路径；原始配置键、枚举值和用户内容保持其身份。动态文字保留有界兼容翻译，不以禁用翻译换取更低开销。

已发布 0.3.0-rc.1 是对照基线。本轮在独立分支构建，完成行为回归、基准及本机实际窗口验证前，不替换公开发行资产。

## 原生处理范围

VideoExport 已使用其原生中文和本项目的 25 项字典校正；AniMorph 部分 F1 元数据和 Expression Studio 的主要窗口已有内置中文。LightSettings 在创建控件或更新下拉显示时设置中文，保留供原插件匹配的枚举文本。MaterialEditor 等插件仍保留 XUnity 的专属词表路径。

Coordinate Load Option 的已核验版本会在检测到翻译器后切回英文。新增适配器按资源键直接提供中文，限定 Studio 进程及原插件/英文资源 SHA，显式语言请求和未知键继续走原逻辑。它不改原 DLL、配置身份或全局文化设置。24 个资源键的检查覆盖了其中未在 Studio 使用的键，不能表述为 24 个可见控件均已实测；硬编码 All 等仍需原有翻译路径。

## 函数级测量

同机 .NET 10、关闭分层 JIT，预热后交替或分进程对照，完整环境与计数见 [performance-validation.json](../sources/performance-validation.json)。

| 路径 | 原开销 | 优化后 | 保留的边界 |
| --- | --- | --- | --- |
| F1 普通查词 | 约 610 B/次 | 0 B/次 | 五字段身份和原配置值不变 |
| F1 未启诊断的观察 | 312 B/次 | 0 B/次 | 启用诊断时仍保存完整观察身份 |
| 动态正则缓存命中 | 112 B/次 | 0 B/次 | 全局回退、正则顺序与负例缓存不变 |
| 动态负例缓存命中 | 120 B/次 | 0 B/次 | 有界 LRU 保持 2,048 项 |
| 重复标签字形覆盖 | 约 67.8 ms/20 万次 | 约 7.7 ms/20 万次 | 缺字仍走后备字体；首次文本仍需查字形 |

字体新增缓存仅存当前字体资源中的短文本，最多 1,024 项，超过 512 字符不保留整段结果。侧栏沿用原扫描间隔和布局策略，改用 Unity 提供的 List 重载及复用清理缓冲区；本轮没有将这部分静态减少分配的结论换算成帧率。

CRLF 文本规范化仍约 150 B/次；首次动态文本仍需规则求值；开启验收诊断仍有额外记录成本。回调反射、Harmony、Unity 绘制及 GPU 没有完整总成本测量。

## 验证结论边界

三项实现均经独立只读复核。Coordinate 的 43 项显式安装验收包括目标 DLL/资源/IL 身份及候选前缀托管调用，未调用 Unity UI。常规 tests 中仅保留合成数据；需要安装版程序集的验证入口在 tools 下显式运行。

所有已盘点文字有处理决定，不等于所有插件的每个动态窗口都已逐一目视验收。0.3.0-rc.1 继续作为公开回退基线；本候选的真实窗口结果及发布状态在验证完成后单独记录。
