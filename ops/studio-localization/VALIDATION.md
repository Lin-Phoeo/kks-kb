在用户已验收的 1.1.0 上整理交互并修正可复现的失败回退。实际候选方法故障检查 11 项通过，旧版同工具出现 6 项失败；字体选择模型 1,013 项、中文名称目录 51 项通过；真实 CM19 注册、配置顺序和布局 finally 独立复核通过。最终版本已备份安装。用户决定不再进行最后一轮手工验收，因此1.1.1新搜索面板、像素布局和实际无效文件恢复没有新增实机确认；保留此边界，按已有离线与1.1.0运行证据预发布。[最后一轮记录](records/font-panel-final-2026-11-27.md)保留范围。

## 已实机验收的字体交互 1.1.0

在 1.0.7 默认中文已获用户确认的基础上，增加独立加粗、−2 到 +3 字号微调、后台中文字体筛选和原家族名对应中文显示。侧栏为 1.3.0，统一读取样式设置。6,610 项状态检查、41 项合成字体检查、29 个真实挂钩元数据检查及独立复核通过；用户确认加粗、字号、列表和恢复正常并退出；日志记录18次字体切换、20次设置应用，字号0/1/2及加粗开关均触发，字体与布局失败0。活动侧栏快照仅9控件，缺字和溢出0；退出快照0控件不作为视觉证据。[字体交互记录](records/font-controls-2026-11-27.md)单独记录这一阶段，先前字体验收不替代新控件验证。

## 性能与服装兼容

本候选在 0.3.0-rc.1 基线上优化 F1 目录查询、动态缓存、字体字形覆盖和侧栏扫描，并新增 Coordinate Load Option 的资源键中文适配。首次实际常用界面验收正常，但随后服装载入触发 DBDE / AssetImport 对英文显示文字的依赖；该回归及修复见[服装兼容记录](records/coordinate-consumer-regression-2026-11-27.md)。最终适配器为 1.0.1，91 项离线检查通过，替换模式读取真实状态，实际追加模式的原有限制保持。

字体策略最终保留原中文为新配置默认，已有用户选择保留。性能与服装记录见[性能记录](records/performance-2026-11-27.md)。服装1.0.1实机记录替换检查2次、真正追加拒绝2次，说明中文误判已修；真正追加支持并未新增，其他临时角色异常另记。

全部插件的未打开动态窗口与未触发原生对话框没有逐一目视验证。旧 ConsoleLogListener Invalid handle 退出问题仍存在，已与翻译适配器的运行结果分开记录。

后续 PerspectiveX 实机发现 IMGUI 的高频文本路径关闭了普通正则查询。上述动态检查调用允许正则的缓存入口，不能覆盖这条实际绘制路径。新增桥接后的 7/7 真实绘制内容检查通过，观测到原 Core 返回原文、桥接提供中文，原缓存没有被修改。对应本机匹配器 6,740 项检查通过，公开清洁规则的检查另列。

字体控制器 1.0.2 实际搜索框验收失败。原字体 lineHeight 为 15、空文本高度约 21，路径创建的旧 Font 在 fontSize 为 14 时 lineHeight 仍为 0。该失败结果保留，随后将旧 uGUI/IMGUI 的 OS Font 与 TMP 路径字体分开处理。

1.0.3 使用已注册字体家族创建旧系统 OS Font，并要求有效行高，TMP 保留文件来源。没有可用系统家族或度量失败时保留旧字体。实际完成 9 次切换观测，涉及宋体、楷体、微软雅黑和华文细黑，可见 TMP 缺字最大值为 0。用户确认“切换、恢复和搜索都正常，流畅，已退出”，最终布局错误、新运行故障和原生崩溃标记均为 0。

历史 rc.1 字体控制器为 1.0.4，只在已验证算法上调整首次配置默认值和快捷按钮，默认启用宋体，并保留楷体快捷选择。24 项默认策略及配置注册检查通过。用户此前已实际切换过宋体，1.0.4 默认值改动没有再次作为新一轮重启实测。已有用户配置由 BepInEx 保留。微软雅黑因部分原面板截短，保留可选但不列为推荐项。[最终范围与构建身份](sources/final-runtime-validation.json)

120 帧稳定观测中，控制器 Update 部分平均约 0.002–0.007 ms。这不包含 Harmony 钩子、字体绘制、原生 GPU 和游戏其他负载，不能表述为整个字体功能的完整性能基准。退出仍有 8 条旧控制台 Invalid handle，已按独立旧问题保留。

公开包的动态桥目录从本包清洁词表重建，含 5,204 个精确项和 231 条规则，实际 RuleMatcher 完成 5,551 项托管检查。长文本上限 12,000 字符，正则输入上限 400 字符，单规则 10 ms 超时，LRU 上限 2,048 项。此检查验证匹配器及公开数据，GUI 钩子的 7 项实机证据具有单独范围。[公开规则验证](sources/public-rule-validation.json)

公开基础包仅包含许可明确的新增值。与完整本机版本的数量差异由 sources/distribution-coverage.json 精确记录。optional-import 在输入具备相同来源值时补齐其余条目，无法匹配的内容明确列为缺失。

本候选另含 4,023 上下文版本的双语标题修订，其验证记录独立于上述 4,020 项整包。不能用前一轮的 184 个绘制身份为后来全部新增功能作证明。

24项单元回归包含18项安装/导入检查和6项合成PE路径检查，使用临时伪游戏目录和自造文件，不读写真实游戏。覆盖带空格与中文路径、Windows 短路径规范化、预检不写入、完整安装/回滚、同名未知文件保护、用户修改后的拒绝回滚、中途第二文件失败恢复、回滚隔离后恢复中断再续跑、可选依赖跳过、Core 计划升级依赖、嵌套词表优先级及路径越界。

rc.2包在隔离目录验证700个清单项，其中693个安装、7个可选项因未放入依赖而跳过。重复安装为零变更，回滚恢复 Core 和配置，并移除本次新建的空插件词表目录。该检查使用公开官方 Core 和临时伪游戏入口，没有启动游戏。[检查摘要](sources/package-fixture-validation.json)

可选导入工具使用 .NET 10 和实际 Core parser，在固定社区归档、本机受检 TXT、显式显示目录三个输入组合下分别核验结果。[导入结果](sources/import-validation.json)

原插件 API 的不同版本需独立适配。release-components.json 和 manifest.json 使用哈希定义已审身份。未匹配的可选插件不会强行替换，核心不匹配则停止。
