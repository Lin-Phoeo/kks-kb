# Coordinate 原生中文与消费者兼容

1.0.1 修复了一个跨插件约定：受检的 DBDE 与 AssetImport 从 Coordinate 的可见按钮文字判断载入模式，又从可见标签判断空槽。仅翻译 Coordinate 资源会把“替换模式”误判为不支持的追加模式。

适配器限定 CharaStudio，并核对 Coordinate DLL、资源以及存在的两个消费者的 SHA。两个消费者使用软依赖排序；只有检查通过并安装局部兼容后才启用原生中文。未知版本、方法或 IL 结构会退回原路径，避免留下已中文但不兼容的语义标签。

发生失败或退出时先关闭原生翻译，再逐项尝试撤销自己的挂钩；某一项撤销失败不会跳过其他项。无论撤销结果如何都清理模式／诊断回调，日志以 `cleanupFailures` 报告失败数，不把失败清理标为完整恢复。

每个受检消费者只改两个比较调用。模式读取 Coordinate 自己的 `addAccModeFlag`，启动时生成直接字段读取委托；按钮缺失时保持原拒绝行为，真实追加模式仍不受支持。空槽判断在这两个调用点兼容原 `Empty` 和本适配器的“空”，不修改物件名字。这仍存在显示名称恰好为“空”的真实饰品被当成空槽的歧义，类似原实现对 `Empty` 的歧义；本修复未重写饰品数据模型。

运行时第一次看到替换、追加、缺少按钮／模式、空槽会分别记录一次 `STUDIO_COORDINATE_COMPAT_DECISION`，没有逐帧日志；退出记录总计。诊断日志失败不会中断服装转移。

离线验证位于 `tools/verify-coordinate-native`。它读取指定的受检 DLL，核对资源、依赖和真实比较 IL，并执行原始与修复后的比较切片；不会启动 Unity、读取人物卡或执行实际服装／资源转移。因此仍需用同一服装操作检查 DBDE／AssetImport 警告、替换结果和正常退出。
