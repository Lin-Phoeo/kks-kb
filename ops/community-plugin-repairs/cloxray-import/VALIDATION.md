# 验证范围

同一组合成输入执行官方和候选 DLL 的实际 CIL。提取范围包括 `OnSceneLoad`、`ToIntArray`、`RestoreWombState` 工厂及完整六个迭代器方法；候选另执行实际 `CaptureImportObjects`。字典复制、记录查找、循环、空检查、object[] 转换、yield 状态机和选择恢复目标的分支全部来自输入 DLL。

Unity 对象/销毁判定、计时、协程调度、KKAPI 保存数据访问、MaterialEditor wearer 推断和最终状态应用是独立合成替身。`ReattachWhenLiquid` 是记录调用映射的替身，BP 重新绑定和 capture poll 不执行。测试验证目标选择和恢复分派，不运行真实游戏 DLL 的材质、IK 或 GPU 代码。

原协程的全局 `FindObjectOfType` 就绪检查仍保留；它只决定等待时机，不提供恢复对象。Import 的对象查询和枚举改用本次映射，不能把这项修复描述成完全移除了所有全局对象搜索。

| 情形 | 要求 |
|---|---|
| 源 ID10 导入为 ID25，目标已有 ID10 | 仅 ID25 接收 pair、stack 和 collapse；旧 wobble 映射调用保留 |
| 两次 Import 共享源 ID10 | 两协程各自处理本次对象；修改传入字典和清空全局表不能改变已捕获目标 |
| 旧保存数据没有新字段 | 仅对本次导入物件执行推断，不扫描已有场景物件 |
| 普通 Load | 原全局对象表和原延迟查询时机保留，已有缓存清理规则保留 |
| Clear | 不恢复物件状态，不增加原先没有的场景载入标记 |
| 空/null map、缺失 ID、空对象、无 guide、已销毁对象 | 不回到全局查询，不误写已有对象 |
| 记录结尾三元组不完整 | 已有完整记录正常处理，尾部忽略 |
| PluginData 为 null、object[] 格式记录 | 原推断和转换保留，仍仅处理导入对象 |

总计 25 个断言。官方对照出现 13 个预期失败，候选全部通过。三个独立拒绝用例检查补丁输入/输出保护。`check-scope.ps1` 按实际 CIL 和异常处理区域检查 3 个原方法变化、776 原方法保留、保存方法及程序集引用不变。

所有生成的候选、抽取 CIL、日志和第三方代码都保留在使用者指定的外部产物目录。公开目录不包含这些文件。合成结果不能推断资源装载、GPU、用户场景往返或主游戏兼容全部通过。
