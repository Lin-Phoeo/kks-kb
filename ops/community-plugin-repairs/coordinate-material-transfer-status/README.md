# CoordinateLoadOption：保留部分成功的材质迁移结果

衣装材质迁移和移除按属性列表逐项操作。目标版本每处理一条先把共享成功标记设为true，遇到缺失Renderer或Material又设为false；因此“前一条成功，最后一条缺失”会跳过目标数据与纹理字典备份刷新，而相同条目换个顺序就会刷新。备份是列表副本，未刷新会与已经修改的控制器数据不一致。

本工具只修两条回调中的状态累计：保留初始false，每次原目标控制器的反射包装调用正常返回后设为true，缺失项不清掉前面已处理的标记。原名称精确匹配、坐标和槽位过滤、调用及顺序、缺失警告、反射包装自身的异常语义、纹理导入流程保持。没有实际调用的空纹理记录不触发备份刷新。

原Extension.Reflection._Invoke会捕获底层异常、记录错误并返回null；正常void方法同样返回null。本工具不修改该包装器，也无法凭返回值区分这两种情况。因此这里的累计表示“包装调用已返回，应重新读取控制器快照”，不保证底层材质操作成功。初版合成边界直接抛错只覆盖了逃出包装边界的异常，不能用它声称原插件底层异常都会向外抛出。

它**不补齐缺失材质**，不新增材质、不模糊匹配名字、不删除保存条目，也不改变插件权限。Missing Material提示仍会如实存在；旧材质复制名称、目标资源或衣装加载时机等原因需要另外核对。本项不能被描述为“所有衣装资源问题已解决”。

需要.NET 10 SDK、Python，以及用户现有的精确原DLL、游戏参考程序集与Mono.Cecil。输出必须是新的仓库外私有目录，不能是游戏运行或内容目录。

```powershell
py ops/community-plugin-repairs/coordinate-material-transfer-status/run.py `
  --original /path/to/KKS_CoordinateLoadOption.dll `
  --game-root /path/to/KoikatsuSunshine `
  --output /path/to/new/private-coordinate-verification
```

验证器提取17段实际CIL，包括完整Set/Remove父循环、相关编译器闭包及作者原ForEach。材质查找、反射调用和目标控制器是自造协作者，不加载用户人物或纹理。测试直接验证最后缺失项导致备份刷新的顺序依赖，不是重写算法作为对照。
