# KKS中文变方框怎么办？先确认缺字，再换对字体

这次排查里，同一段中文放到MS Gothic中，缺了13个常用简体字；换成系统已有的Microsoft YaHei后，样本缺字变成0。

样本是这句：

> 材质编辑器读取场景设置插件配置轮廓法线导出对象碰撞保存恢复简体中文测试

问题看起来像“汉化没生效”，实际有一部分是字已经翻译出来了，当前字体却画不出来。下面只讲字体问题，不需要重装整合包、升级一堆插件，也不用改翻译模型或代理。

## 先分清你遇到的是哪一种

如果总是几个相同的汉字变成方框或空白，而旁边文字正常，优先查缺字。最好把那几个字单独记下来，后面用同一组字验收。

如果整句话成了“锟斤拷”或其他错误字符，先查文本文件和读取方式的编码。把坏掉的文字换个字体，通常还是坏的。不要一上来把整个翻译目录批量转成UTF-8，原文件可能需要别的编码。

如果字都对，只是太小、发虚或挤出按钮，先看游戏、插件自己的UI缩放和系统DPI。这是字号或布局问题，未必需要换字库。

## 同一个游戏里，文字不一定由同一种UI画出来

这是最容易绕弯的地方。XUnity.AutoTranslator里有几个名字相近的配置，但作用范围不同：

| 界面类型 | 对应方向 |
|---|---|
| UGUI | 确认系统字体有目标字，再考虑`OverrideFont` |
| TextMeshPro，简称TMP | 优先检查`FallbackFontTextMeshPro` |
| IMGUI插件窗口 | 找该插件自己的GUI字体或缩放设置 |

官方文档明确写了：`OverrideFont`只对UGUI有效。它不会因为名字叫“覆盖字体”，就顺便接管所有插件面板。只看到某个菜单变正常，也不能宣布全游戏字体都修好了。

## 动手前，退出游戏并备份配置

先找到实际安装目录和正在使用的AutoTranslator配置，常见位置是`BepInEx/config/AutoTranslatorConfig.ini`。确认是这一份，再复制备份并记下修改前哈希。游戏运行时可能会保存设置，边开着边改容易互相覆盖。

只改需要的键，不要拿别人的整份INI覆盖自己的。翻译接口、语言、已有缓存、账号与网络设置都不属于这次字体修复。

### UGUI缺字：字体必须在这台机器上真实存在

在这次Windows环境里，Microsoft YaHei已经安装，目标中文也在它的cmap里，所以使用了：

```ini
[Behaviour]
OverrideFont=Microsoft YaHei
```

这只是经过本机检查后的选择。你的系统没有微软雅黑，或者缺的是另外一组罕见字，就应选择实际存在、覆盖目标字的字体。字体文件放进某个文件夹，也不一定等于已经按系统字体名可用。

### TMP缺字：优先加后备字体

TMP的fallback会在原字体缺字时提供字形，官方推荐先考虑它，而不是直接覆盖所有TMP文字。

本次Unity2019环境已有一份字库，于是设置为：

```ini
[Behaviour]
FallbackFontTextMeshPro=BepInEx/Translation/fonts/arialuni_sdf_u2019
```

**这行是实例，不是通用下载指令。** 路径相对实际游戏根目录，必须真的存在，资源也要适合你的Unity/TMP版本。不要照着文件名找来一个不明包，更不要把普通TTF文件随便改名成这个名字。旧TMP也不能默认像UGUI一样直接填系统字体名就能动态生成可用字库。

本次字库有33932条字符记录，测试句没有缺字；但它不包含全部汉字。启动还出现了字体资产1.1.0与运行TMP1.4.0的版本警告，之后才成功加载。能加载、能显示这几个菜单，是本次的验证结果，不是对其他机器的保证。

## 保存后，要回到出问题的界面看

重新启动游戏，先看启动日志里是否有字体载入失败，再打开原来缺字的菜单。至少核这几件事：

1. 原来缺的字是否显示，翻译内容本身有没有变。
2. 按钮、下拉框、列表是否被撑开、截断或重叠。
3. 滚动、切换页面后是否仍正常；UGUI、TMP与IMGUI分别看，不混算。
4. 是否新增字体版本、资源载入或缺字错误。

日志显示“已加载”只能证明资源载入了一步，画面仍要实际检查。这次验证了主菜单里的配置、选项、画面效果、保存、读取等文字，没有穷举每个第三方窗口。

如果没有改善，或布局被破坏，就把本次改过的字体键恢复。若游戏启动后又写入了其他配置，优先只回滚那几行，别用整份旧INI抹掉新的设置。

## 想让自己的AI来做，可以直接交这段任务

配套的[完整AI修复提示词](https://github.com/Lin-Phoeo/kks-kb/blob/docs/kks-font-repair-20261126/docs/fonts-guide/AI-REPAIR-PROMPT.zh.md)可以直接复制：让AI先区分缺字/编码/字号，确认实际UI框架，检查字库覆盖，备份后最小修改，启动验收并保留回滚记录。它不依赖这篇文章里的安装目录，也不要求你的配置和本例一样。

任务开头可以这样写，再附上完整提示词：

> 帮我排查这个游戏界面的中文缺字。先判断是字库、编码还是字号问题，查清UGUI/TMP/IMGUI，只改证据支持的字体配置。改前退出游戏并备份，改后回到原页面验证；不要升级无关插件、改模型代理或保存游戏数据。

[字体指南和来源入口](https://github.com/Lin-Phoeo/kks-kb/blob/docs/kks-font-repair-20261126/docs/fonts-guide/README.md)以及[脱敏证据](https://github.com/Lin-Phoeo/kks-kb/blob/docs/kks-font-repair-20261126/docs/fonts-guide/evidence.json)可供核对。发布稿不附字体文件、完整配置或用户日志。把“哪几个字、哪个窗口、改了哪一项、启动后看到了什么”留下来，下一次排查就能接着证据走。
