# 可独立复制给AI的字体排查与修复任务

下面整段可以直接交给有本机读写和界面验证能力的AI。它应根据实际环境执行，不把文中的示例字体或路径当成机器事实。

---

请协助修复我自己安装的KKS/相关Unity游戏中的中文显示问题。目标是让原来缺失的中文正确显示，同时保留已有翻译内容、配置和游戏数据。先诊断后改，只在证据支持的最小范围内操作；不要连带升级插件或重装整合包。

### 1. 确认现象和真实环境

- 从当前工作目录、快捷方式目标、游戏日志或安装文件定位实际游戏目录、正在使用的配置、Unity版本、AutoTranslator版本；不要猜盘符和用户名，不启动安装器。
- 尽量从现有截图/界面和日志找原来出问题的页面，记录具体缺失字符。实在看不到该现象时再向我确认，不假装已经复现。
- 区分三类：相同字符方框/空白可能是字形缺失；“锟斤拷”或错误字符先查文本/读取编码；字符都正确但过小、模糊、裁切先查字号、DPI和布局。不要把三类问题都归因于字体。
- 判断受影响窗口是UGUI、TextMeshPro还是IMGUI；可依据插件文档、已安装版本、相关日志和实际控件。判断不了就标为未知，不强行套用配置。

### 2. 查对应机制，不盲抄示例

- XUnity.AutoTranslator的`OverrideFont`仅针对UGUI。它不能保证修改IMGUI或全部插件窗口。
- TMP优先考虑`FallbackFontTextMeshPro`，为原字体缺字时补字；`OverrideFontTextMeshPro`会改变更大范围，不能在没有证据时直接全覆盖。核对你找到的已安装版本说明。
- IMGUI要查所属插件实际支持的GUI字体/缩放入口；`EnableIMGUI`只开启翻译框架，不保证修复GUIStyle字体。若没有该字体入口，先说明限制，不凭空加一个无效配置键。
- 检查系统是否安装候选字体，以及具体缺失字符是否在其Unicode cmap中；字体名称以实际系统记录为准。不要把缺失某个字等同整个中文字体不可用。
- TMP要检查已持有的资产包、Unity/TMP适配、字符表、字形/atlas引用和目标字符覆盖。相对资源路径按实际游戏根目录解析。普通TTF不等于可直接用的TMP资产包；旧TMP不能默认通过填系统字体名就动态加载，必须核对当前版本支持。
- `Microsoft YaHei`和`BepInEx/Translation/fonts/arialuni_sdf_u2019`只是一台Windows/Unity2019机器曾验证的示例，不能假定我也安装了这些资源，更不能直接照名下载/复制。若确实缺资源，先核官方或可信授权来源和版本，给出明确缺口；不要安装未知字体包或换网络设置。

### 3. 备份与最小修改

- 修改前确认游戏进程已正常退出；不要覆盖仍被程序写入的配置。保留原配置副本、原哈希、大小、编码/换行形式和备份位置。
- 常见配置是`BepInEx/config/AutoTranslatorConfig.ini`，但以实际定位结果为准。只读取需要的字体/framework字段；不把接口密钥、Cookie、token或完整配置/日志发到外部服务。
- 对确认属于UGUI且确实缺字的情况，只修改已有`[Behaviour]`的`OverrideFont`为已验证覆盖目标字符的系统字体。
- 对确认属于TMP缺字的情况，在目标资产真实存在且适配时，只修改`FallbackFontTextMeshPro`；确认原有TextMeshPro支持开关与实际插件版本，避免为了省事全开所有框架。
- 保留其他键、注释、格式和期间用户修改。不要覆盖整份INI，不重复创建同名节/键。修改后回读，生成只含字体相关行的前后差异，并确认没有意外改动。
- 编码问题要保留原始字节，先确认文本来源编码和读取规则，不能批量转码全部翻译文件。纯字号问题优先使用原游戏/插件提供的UI缩放；不要先替换全部字库。
- 不改翻译模型/接口、代理/端口、账号、BepInEx日志开关、游戏EXE/DLL、mods、人物/坐标/场景、存档或其他无关数据。字体修复不需要Compositor等截图补丁。

### 4. 必须启动验收

- 使用正常游戏入口重新启动，只做字体/UI验证，不保存人物、坐标或场景。
- 回到原缺字页面，检查同一组字符是否显示，以及按钮、列表、下拉框、滚动和页面切换是否裁切或重叠。不同框架分别记录结果，不能一个UGUI菜单正常就算全部通过。
- 检查新启动日志中的字体加载、缺字、资源格式和TMP版本警告。资源“加载成功”不等于每个字都能显示；有版本警告但样本可读时，明确保留兼容风险与已验证范围。
- 如果无法启动、没有UI访问能力或原现象不能复现，报告“配置/静态覆盖已核，运行验收未完成”，不要写“已修复”。需要我手动打开页面时，给出具体页面与检查动作。

### 5. 回滚和交付

- 失败或引入新布局问题时，只回滚本次字体键；若能确认整个配置之后无人改过，也可用已核哈希的备份恢复。若文件已漂移，先比较再合并回滚，不覆盖我的新设置。
- 最终简洁说明：原现象与UI框架；根因证据；改动的文件/字体键；备份与回滚方式；实际启动和页面测试结果；仍未验证的窗口或字符。
- 只给脱敏摘要，不公开完整日志、密钥、账号、用户目录或人物/场景文件名。没有完成运行验证时明确写出来，不把“配置可解析”或“cmap存在”当成画面成功。

参考事实供核查，不作我的机器现状：一次2026-11-26排查中，MS Gothic对“材质编辑器读取场景设置插件配置轮廓法线导出对象碰撞保存恢复简体中文测试”缺13字，Microsoft YaHei缺0字；一份33932字符TMP资产静态覆盖该样本但不覆盖全部中文。该资产1.1.0与运行TMP1.4.0有警告后成功加载，UI只验证了部分菜单标签，没有把整句样本注入游戏验证。官方说明可查[XUnity.AutoTranslator固定README字体章节](https://github.com/bbepis/XUnity.AutoTranslator/blob/692e044503f591d58c875e06bea1872b5d2dcc56/README.md#L480)，配置框架边界见[第336行起](https://github.com/bbepis/XUnity.AutoTranslator/blob/692e044503f591d58c875e06bea1872b5d2dcc56/README.md#L336)；当前安装版本与资源仍要自行核对。

---

提示词不要求AI拥有特定工具。若它只能提供文字建议，必须明确哪些操作需由你本人完成，不能声称已经改过配置或看过游戏画面。
